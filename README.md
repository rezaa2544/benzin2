# بنزین ۲ · Benzin 2

بازار دوطرفهٔ سهمیهٔ بنزین برای یک شهر (شروع: بانه). فروشنده سهمیهٔ اضافهٔ کارت سوختش را
آگهی می‌کند، خریدار لات می‌خرد، دو طرف در اپ به هم می‌رسند و کارت سوخت را حضوری تحویل می‌دهند.

> ⚠️ این پروژه کاملاً مستقل از **پایش / Payesh** است. هیچ فایل، کامیت، متن یا وابستگی‌ای از پایش
> نباید در این مخزن ظاهر شود. مرز پروژه در `docs/benzin2/01-ARCHITECTURE.md` تعریف شده است.

### ورود و پنل مدیریت (بدون سرویس پیامک)

سرویس SMS هنوز وصل نیست، پس در بیلد دسکتاپ **کد ورود ثابت `12345`** است و دو حساب آماده وجود دارد:

| شماره         | نقش          | کجا                        |
| ------------- | ------------ | -------------------------- |
| `09187888993` | OWNER (مالک) | هم اپ مشتری، هم پنل مدیریت |
| `09373210545` | کاربر عادی   | اپ مشتری، برای تست خرید    |

روش ورود: شماره را بزنید → «ارسال کد» → در پنج کادر `12345` را وارد کنید → «تأیید و ورود».

در بیلد ۰٫۲٫۲ کد ثابت به انقضا و تعداد تلاش کاری ندارد؛ حتی اگر «کد منقضی شده» دیدید یا اصلاً
کد نخواستید، همان `12345` را وارد کنید و «تأیید و ورود» را بزنید.

پنل مدیریت: منوی **نمایش → پنل مدیریت** (یا `Ctrl+2`). پورت‌ها: `41720` اپ، `41721` API، `41722` پنل —
همه فقط روی `127.0.0.1`.

### این نصب‌کننده چه چیزی است؟

اپ دسکتاپ کامل (Electron) که **API و رابط کاربری را با هم داخل یک پنجره اجرا می‌کند** — بدون
نیاز به اینترنت، سرور یا نصب جداگانهٔ Node. دیتابیس درون‌حافظه‌ای با دادهٔ نمونه است، پس برای
دیدن و تست جریان کار ایده‌آل است؛ برای نسخهٔ واقعی باید Postgres و سرور مستقر شود (`G-18`).

- ورود با OTP: کد پیامک‌شده در نسخهٔ دسکتاپ در لاگ برنامه نوشته می‌شود (SMS واقعی بعد از `G-12`).
- پورت‌های محلی `41720` (اپ) و `41721` (API) فقط روی `127.0.0.1` باز می‌شوند؛ از بیرون در دسترس نیستند.
- ساخت از منبع: `cd desktop && npm install && npm run dist` (پیش‌نیاز: `pnpm install && pnpm -r build` در ریشه).

## این مخزن از کجا آمده

نسخهٔ ۱ (`github.com/rezaa2544/benzin`) یک مونوریپوی کامل است: API با Fastify، پنل ادمین با React،
اپ مشتری با React + PWA، ۵۲ فایل تست، مهاجرت‌های دیتابیس و `infra/` با Docker Compose و Caddy.
کد آن به این مخزن منتقل شده تا از صفر شروع نکنیم؛ اما **در وضعیت فعلی در production بالا نمی‌آید**:
`apps/api/src/main.ts` در حالت production عمداً `exit(1)` می‌کند چون آداپتور Postgres فقط برای
«مناطق» پیاده شده و بقیهٔ مخزن‌ها درون‌حافظه‌ای‌اند. جزئیات و شواهد در `04-REVIEW-v1.md`.

برای رسیدن به «قابل اجرا» کافی است تسک‌های `G-01` تا `G-09` انجام شود؛ تسک‌های `G-10` به بعد
(اندروید، پنل زیرساخت، مقیاس‌پذیری) بعد از اجرای اولیه می‌آیند.

## شروع سریع (محیط توسعه)

```bash
corepack enable && corepack prepare pnpm@9.15.4 --activate
pnpm install
cp .env.example .env
pnpm -r build && pnpm -r test
pnpm dev:api     # http://localhost:3000  (مخزن درون‌حافظه‌ای + دادهٔ seed)
pnpm dev:admin   # http://localhost:5174
pnpm dev:web     # http://localhost:5173
```

کل استک با دیتابیس واقعی:

```bash
cd infra && docker compose up -d   # Postgres/PostGIS + API + web + admin + Caddy
```

## قواعد غيرقابل‌مذاکره

1. **فارسی و RTL** در تمام رابط کاربری؛ کد، کامیت و نام فایل انگلیسی.
2. **بدون تداخل با پایش.** نام Payesh در هیچ فایلی نیاید.
3. قیمت‌گذاری با عرضه و تقاضا؛ هیچ سقف/کف قیمتی در کد نباشد.
4. رزرو سفارش باید **اتمی در سطح دیتابیس** باشد، نه فقط قفل درون‌پروسه‌ای.
5. انقضا با **کارگر زمان‌بندی‌شده** مدیریت شود، نه با چک هنگام باز شدن اپ.
6. شمارهٔ تماس فقط بعد از رزرو و فقط برای مشترک نمایش داده شود.
