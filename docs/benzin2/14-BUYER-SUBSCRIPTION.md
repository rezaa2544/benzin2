# G-26 + G-19 — اشتراک خریدار و حریم خصوصی شماره

**پذیرش G-26:** پلن‌ها از پنل (نام، قیمت، مدت، سهمیهٔ رزرو)؛ حداقل یک پلن رایگان؛ تغییر قیمت روی
اشتراک‌های فعال اثر نکند؛ خرید ۱۵ هزار تومانی = یک رزرو.
**پذیرش G-19:** شماره فقط با رزرو تأییدشده و پلنی که شماره می‌دهد و `phone_hidden = false` برگردد؛
سوییچ «شماره‌ام را مخفی کن» در پروفایل؛ در حالت مخفی دکمهٔ تماس حذف و فقط چت بماند.

این سند دو تسک به‌هم‌پیوسته را پوشش می‌دهد: **پولی که خریدار می‌دهد چه چیزی می‌خرد** و **شماره
چه زمانی از سرور بیرون می‌رود**. هر دو از یک جا کنترل می‌شوند و هیچ‌کدام در کلاینت تصمیم گرفته
نمی‌شوند.

## ۱) مدل: پلن چه می‌فروشد

طبق `00-PRODUCT.md` درآمد از اشتراک خریدار است، نه کارمزد معامله. فروشنده همیشه رایگان است.
سه چیز فروخته می‌شود و هر سه در جدول `plans` تعریف شده‌اند:

| ستون                   | معنی                                           |
| ---------------------- | ---------------------------------------------- |
| `monthly_reservations` | تعداد رزرو در هر ماه شمسی؛ `NULL` = نامحدود    |
| `phone_visible`        | آیا این پلن حق دیدن شمارهٔ طرف مقابل را می‌دهد  |
| `single_use`           | پلن اعتباری تک‌رزرو: با اولین رزرو مصرف می‌شود |

پلن‌های پیش‌فرض:

| پلن                        | قیمت    | رزرو در ماه | شماره | تک‌رزرو |
| -------------------------- | ------- | ----------- | ----- | ------- |
| رایگان `free`              | ۰       | ۳           | ✗     | ✗       |
| اعتباری (تک‌رزرو) `single` | ۱۵٬۰۰۰  | ۱           | ✓     | ✓       |
| اشتراک یک‌ماهه `monthly`   | ۴۹٬۰۰۰  | نامحدود     | ✓     | ✗       |
| اشتراک سه‌ماهه `quarterly` | ۱۲۹٬۰۰۰ | نامحدود     | ✓     | ✗       |

هیچ عددی در کد نیست: قیمت و سهمیه از پنل («پلن‌ها») ویرایش می‌شوند و تغییر قیمت به اشتراک‌های
فعال دست نمی‌زند، چون پول پرداخت‌شده روی ردیف پرداخت و `planId` روی اشتراک قفل است.

**اعتبار:** ستون `duration_days` هر پلن است و مالک هر عددی بخواهد می‌گذارد؛ seed عدد ۹۰ را برای
پلن تک‌رزرو و ۳۰ را برای ماهانه می‌گذارد، ولی هیچ‌کدام در کد نیست. `0` یعنی **بدون انقضا**: اعتبار
تا مصرف‌شدن می‌ماند. مصرف‌شدن در `subscriptions.consumed_at` ثبت می‌شود و `findActiveByUser` بعد از
آن، اشتراک را برنمی‌گرداند. (فرض A15 که ۹۰ روز را یک قاعده می‌دانست، با G-29 بسته شد.)

## ۲) یک جا برای همهٔ پاسخ‌ها

`EntitlementService` تنها مرجعی است که می‌گوید یک خریدار چه کاری می‌تواند بکند:

```ts
GET /v1/me/entitlements
{
  "planCode": "free", "planNameFa": "پلن رایگان", "source": "FREE", "active": false,
  "phoneVisible": false, "monthlyLimit": 3, "usedThisMonth": 2, "remaining": 1,
  "singleUse": false, "needsPurchase": false, "endsAt": null
}
```

- **ماه شمسی تهران** مبنای سهمیه است (نه ۳۰ روز غلتان): «۳ رزرو در ماه» باید با تقویم مردم
  بخواند. یک رزرو ساعت ۲۳:۳۰ آخر ماه به ماه خودش تعلق می‌گیرد.
- کاربر بدون اشتراک، سهمیهٔ پلن رایگان را می‌گیرد. اگر مالک تنظیم
  `subscription.required_for_orders` را روشن کند، سهمیهٔ رایگان صفر می‌شود («هیچ رزرو رایگانی نیست»).
- همهٔ رزروهای شروع‌شده شمرده می‌شوند، حتی لغوشده‌ها؛ وگرنه سهمیه با لغو کردن دور زده می‌شود.

**دروازه:** `POST /v1/orders/:id/reservations` اول از `requireForReservation` می‌پرسد. با تمام‌شدن
سهمیه:

```
429 RESERVATION_QUOTA_EXHAUSTED
{ "planCode": "free", "monthlyLimit": 3, "usedThisMonth": 3, "cheapestPlanToman": 49000 }
```

عددها همراه خطا می‌آیند تا اپ بتواند مستقیم پیشنهاد پلن بدهد (و در پنل خریدار بداند چرا). پلن
تک‌رزرو **بعد از** ساخته‌شدن رزرو مصرف می‌شود؛ اگر خریدار در مسابقهٔ رزرو ببازد، اعتبارش نمی‌سوزد.

## ۳) شماره: سه شرط، همه لازم

`GET /v1/reservations/:id/contact` فقط وقتی شماره می‌دهد که:

1. درخواست‌کننده یکی از دو طرف رزرو باشد و صاحب سفارش پذیرفته باشد (قاعدهٔ قدیمی E4-05)؛
2. پلنش `phone_visible` داشته باشد؛ وگرنه `402 PHONE_REQUIRES_SUBSCRIPTION` با `chatOnly: true`؛
3. طرف مقابل `phone_hidden = true` نکرده باشد.

اگر شرط ۳ برقرار نباشد، پاسخ ۲۰۰ است ولی شمارهٔ مخفی **در payload نیست**:

```json
{
  "chatOnly": true,
  "hidden": { "owner": true, "taker": false },
  "owner": { "id": "…", "phone": null },
  "taker": { "id": "…", "phone": "0912…" }
}
```

یعنی خریدار شمارهٔ خودش را می‌بیند، شمارهٔ فروشنده را نه، و اپ به‌جای دکمهٔ تماس، «رفتن به چت»
نشان می‌دهد. حریم خصوصی هرگز معامله را نمی‌بندد: چت درون‌برنامه باز است (G-27) و پیام‌ها تا
قبل از تأیید هم شماره را ماسک می‌کنند.

**آدیت:** هر فراخوانی `contact.revealed` ثبت می‌شود، با `by` (کدام طرف) و `hidden` (کدام شماره
داده نشد) — بدون خودِ شماره.

**سوییچ:** `PATCH /v1/me { "phoneHidden": true }` — می‌تواند تنها باشد، بدون فرستادن نام؛ تغییری
در نام هم `user.profile_updated` با `phoneHidden` ثبت می‌شود.

## ۴) رابط‌ها

- **صفحهٔ پلن‌ها:** کارت «وضعیت اشتراک شما» بالای فهرست («۱ از ۳ رزرو این ماه باقی مانده» یا
  «رزرو نامحدود · ۵ رزرو تا امروز») و در هر کارت پلن، دو خط: چند رزرو در ماه و آیا شماره می‌دهد.
- **پروفایل:** سوییچ «شماره‌ام را مخفی کن» با توضیح «هماهنگی از چت انجام می‌شود».
- **صفحهٔ معامله:** دکمهٔ «نمایش شماره تماس» می‌ماند، ولی در حالت مخفی به‌جای شماره، پیام
  «طرف مقابل شماره‌اش را مخفی کرده است…» و دکمهٔ «رفتن به چت».
- **پنل پلن‌ها:** فیلد «رزرو در ماه» (خالی = نامحدود)، چک‌باکس‌های «دیدن شماره» و «تک‌رزرو».

## ۵) داده

مهاجرت `0012_buyer_entitlements.sql`:

- `plans.monthly_reservations smallint` (null = نامحدود)، `plans.phone_visible boolean`،
  `plans.single_use boolean`؛
- `subscriptions.consumed_at timestamptz`؛
- `users.phone_hidden boolean NOT NULL DEFAULT false`.

### چیزهایی که عمداً انجام نشد

- **قیمت اعتبار تک‌رزرو** در جدول `plans` است، نه در کد؛ اگر مالک ۱۵ هزار را به ۲۰ هزار تغییر دهد،
  هیچ تستی نمی‌شکند (تست‌ها از پلن seed می‌خوانند).
- **ارتقای خودکار** (proration) نداریم: خرید پلن دوم، پلن قبلی را باطل نمی‌کند؛ `findActiveByUser`
  دیرترین پایان را برمی‌گرداند. برای MVP درست است، برای نسخهٔ بعد یک تصمیم محصول است.

## ۷) G-29 — همه‌چیز از پنل، هیچ‌چیز در کد

فهرست چیزهایی که مالک می‌تواند بدون deploy عوض کند:

| تنظیم                                | کجا                                                | اثر                                                                  |
| ------------------------------------ | -------------------------------------------------- | -------------------------------------------------------------------- |
| قیمت هر پلن                          | پنل → پلن‌ها                                       | فقط خریدهای بعدی؛ مشترک فعلی همان چیزی را که پرداخت کرده نگه می‌دارد |
| اعتبار (`duration_days`)             | پنل → پلن‌ها                                       | ۰ = بدون انقضا (تا مصرف شدن)                                         |
| رزرو در ماه (`monthly_reservations`) | پنل → پلن‌ها                                       | خالی = نامحدود؛ عدد = سهمیهٔ ماه شمسی                                 |
| دیدن شماره (`phone_visible`)         | پنل → پلن‌ها                                       | کل حق دیدن شماره                                                     |
| تک‌رزرو (`single_use`)               | پنل → پلن‌ها                                       | اشتراک با اولین رزرو مصرف می‌شود                                     |
| بازنشستگی پلن (`is_active`)          | پنل → پلن‌ها                                       | پلن از فهرست خرید حذف می‌شود، خریدهای قبلی معتبر می‌مانند            |
| «هیچ رزرو رایگانی نیست»              | پنل → تنظیمات (`subscription.required_for_orders`) | سهمیهٔ پلن رایگان صفر می‌شود                                          |

`planWindowEnd(start, days)` تنها جایی است که پنجرهٔ اشتراک محاسبه می‌شود (خرید، تأیید پرداخت،
تسویهٔ دوبارهٔ پرداخت‌های جاافتاده)؛ سه نسخهٔ تکراری قبلی حذف شد تا «۹۰ روز» فقط یک معنی داشته باشد.

تست‌ها (`apps/api/test/g26b-plan-config.test.ts`): پلن ۱۵ روزه → اشتراک دقیقاً ۱۵ روز؛ پلن ۰ روزه →
۳۶٬۵۰۰ روز و سهمیهٔ نامحدود؛ تغییر پلن بعد از خرید، مشترک فعلی را تغییر نمی‌دهد ولی خریدار بعدی را
می‌دهد؛ پنجرهٔ ۳۶٬۵۰۱ روزه با ۴۲۲ رد می‌شود.
