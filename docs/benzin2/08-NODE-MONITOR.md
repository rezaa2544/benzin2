# نظارت زنده و گرهٔ کمکی (G-28)

هدف: سیستم مالک در نقش «سرور کمکی» بالا بیاید و در همان حال، مصرف واقعی سی‌پی‌یو/رم/دیسک و
گزارش کاری که انجام می‌دهد در پنل ادمین دیده شود — بدون اینکه تا سالم بودن سرور اصلی مزاحمتی
ایجاد کند.

## ۱) صفحهٔ پنل

`https://<host>/admin/#/nodes` — هر گره یک کارت دارد:

| بخش                                 | معنی                                                        |
| ----------------------------------- | ----------------------------------------------------------- |
| سی‌پی‌یو / حافظه / دیسک             | مصرف همان لحظه؛ نوار سبز/زرد/قرمز (۶۰٪ و ۸۵٪)               |
| درخواست در دقیقه، میانگین پاسخ، خطا | شمارندهٔ ترافیک همان گره (پنجرهٔ یک‌دقیقه‌ای)                 |
| تغییرهای انجام‌شده + گزارش کار      | پاک‌سازی‌هایی که این گره اجرا کرده، با تفکیک تعداد هر تغییر |
| وضعیت                               | «فعال» / «آماده‌به‌کار» / «آفلاین» + جملهٔ وظیفه             |

صفحه هر ۴ ثانیه خودش را تازه می‌کند (وقتی تب پنهان شود، نظرسنجی می‌ایستد).

## ۲) تنظیمات سرور

| متغیر                   | پیش‌فرض             | کار                                                               |
| ----------------------- | ------------------- | ----------------------------------------------------------------- |
| `NODE_ROLE`             | `primary`           | `helper` یعنی «خودم زمان‌بند را استارت نزنم تا سرور اصلی قطع شود» |
| `NODE_ID`               | `<role>-<hostname>` | شناسهٔ پایدار گره                                                  |
| `NODE_NAME`             | «بنزین — اصلی/کمکی» | نامی که در پنل دیده می‌شود                                        |
| `NODE_TOKEN`            | —                   | رمز مشترک ایجنت بیرونی؛ بدون آن مسیر heartbeat بسته است (۵۰۳)     |
| `NODE_HEARTBEAT_MS`     | ۱۰۰۰۰               | فاصلهٔ نوشتن ضربان                                                 |
| `NODE_STALE_SECONDS`    | ۹۰                  | بعد از این مدت سکوت، سرور اصلی «از کار افتاده» حساب می‌شود        |
| `NODE_FAILOVER_POLL_MS` | ۱۵۰۰۰               | فاصلهٔ پرسش گرهٔ کمکی                                               |

## ۳) بالا آوردن سرور کمکی

روی سیستم دوم، همان بیلد + همان `DATABASE_URL` (ضربان‌ها باید در یک جدول مشترک بنشینند):

```bash
NODE_ROLE=helper NODE_ID=pc-reza NODE_NAME="سیستم رضا" DATABASE_URL=... node dist/main.js
```

از این لحظه گرهٔ کمکی هیچ کاری نمی‌کند جز ضربان فرستادن؛ به‌محض اینکه هیچ سرور اصلی‌ای
`NODE_STALE_SECONDS` ثانیه گزارش ندهد، زمان‌بند انقضا را استارت می‌زند (قفل advisory همان
`sweep` تضمین می‌کند دو گره هم‌زمان یک ردیف را دوباره اعمال نکنند) و وقتی سرور اصلی برگشت،
دوباره پارک می‌شود.

## ۴) ایجنتی که فقط ضربان می‌فرستد

اگر نمی‌خواهید کل API روی سیستم دوم بالا بیاید، ایجنت سبک را اجرا کنید:

```bash
API_URL=http://<primary>:41721 NODE_TOKEN=<همان NODE_TOKEN> \
NODE_ID=pc-reza NODE_NAME="سیستم رضا" NODE_INTERVAL_MS=5000 \
node scripts/helper-node.mjs
```

هر دور، یک خط گزارش در کنسول می‌نویسد (`cpu … ram … disk … | standby|ACTIVE | reason`) و همان
اعداد را به `/v1/nodes/heartbeat` می‌فرستد. اگر `HELPER_TAKEOVER_CMD` تنظیم شود، هنگام فعال شدن
آن فرمان را اجرا (مثلاً یک نمونهٔ API) و با برگشت سرور اصلی متوقفش می‌کند. برای یک اجرای آزمایشی:
`--once`.
